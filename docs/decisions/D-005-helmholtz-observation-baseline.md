# D-005: Helmholtz observations on the truth model as the starting baseline

Status: Proposed
Features: F-006
Source: 2-feature-inventory (retrospective)
Supersedes: —
Superseded by: —

## Context
Observed data are generated by a Helmholtz solve on the truth model with the
same frequency-domain operator the inversion uses (README "Important
points": "a deliberate inverse-crime baseline"). Since `7c130ad` removed
`leapfrog_fft` observations (D-004), this is the only observation path.

## Decision
Use Helmholtz observations on the truth model (inverse crime) as the
baseline while the inversion is being developed.

## Alternatives
Observations from an independent forward model (e.g. the removed
`leapfrog_fft` path, a different discretisation or an external solver).
None is currently implemented.

## Rationale
Observed: `odil_wave/experiment/problem.py` builds observations with
`HelmholtzSolver`; `tests/test_experiments.py` checks that observed data
satisfy the inverse operator on the truth model.

Maintainer statement (local session, 2026-10-22): "make the problem simpler
at the start (this will have to be changed once good results are obtained)".

## Consequences
Interpretation (inventory author, not part of the maintainer statement):
- The inversion can, in principle, reproduce its data exactly, which isolates
  optimiser behaviour from modelling error.
- Reconstruction quality under this baseline overstates what can be expected
  with independent or real data.

## Scope and limitations
Temporary by intent. No results obtained under this baseline are evidence of
performance without the inverse crime.

## Revisit when
Good results are obtained on this baseline (the maintainer's stated trigger),
at which point an independent observation path is required.
