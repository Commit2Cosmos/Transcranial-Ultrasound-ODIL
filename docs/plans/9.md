## Objective
Fill in `docs/features.md` with the project's existing capabilities, based on
what the repository shows at the time of implementation. Issue #9 requires
that:

- every major capability found during inspection is listed, with a stable
  F-ID and repository references;
- implementation evidence (the code exists) is kept apart from correctness
  evidence (tests, reports, reference comparisons);
- unknown status, missing verification and missing rationale are stated, not
  left blank;
- retrospective decision records are written only where evidence supports
  them, and no rationale is invented;
- `docs/reports/9.md` says what was inspected and where coverage is limited.

The change is documentation only. Application code, tests, dependencies and
workflows stay unchanged, and no expensive numerical experiments are run.

## Proposed approach
### Granularity
One entry per user-meaningful capability. The proposed list is below; the
final wording and order are settled during implementation.

Planned entries (provisional status in brackets):
1. 2D space/time grid with PML sponge and non-dimensionalisation, plus
   frequency-bin selection [Experimental]
2. Source wavelets: tone burst and Ricker [Experimental]
3. Ring transmission acquisition geometry [Experimental]
4. Built-in velocity phantoms: Shepp-Logan, skull variants, homogeneous,
   overdensity [Experimental]
5. Frequency-domain discrete wave operator: FD Laplacians of order 2–10 and
   PML/Neumann conditions [Experimental]
6. Helmholtz forward solver, and synthetic observations generated with it
   (an inverse-crime baseline) [Experimental]
7. ODIL discrete loss: PDE, data and regulariser terms, with Tikhonov and TV
   regularisers [Experimental]
8. Joint full-space ODIL inversion over `u` and `c` with L-BFGS
   (`JointFreqODIL`) [Experimental]
9. Low-to-high multi-frequency continuation bands with warm start
   [Experimental]
10. Reconstruction quality metrics: masked SSIM, MSE, MAE [Experimental]
11. Config-driven reproducible run layer: schema, validation, overrides,
    run artifacts, metadata and failure capture [Experimental]
12. CLI entry point `main.py` [Experimental]
13. Run analysis plots and animations from saved artifacts [Experimental]
14. Example and main notebooks [Experimental, flagged]
15. Stride external reference forward/FWI comparison material
    [Experimental, flagged]
16. Block-coordinate dual L-BFGS optimiser (`LBFGSB`), with u-block Hessian
    and exact u-solve [Removed]
17. Leapfrog time-domain solver, and `leapfrog_fft` observations that avoided
    the inverse crime [Removed]

Candidates that may be merged into other entries or dropped, with the reason
given in the report: the `Wavefield` container (expected to fold into 7 or 8),
the old reproduction/PINN notebooks (notebooks, not capabilities, unless
history shows otherwise), and `operator/_deprecated`.

### Status policy
- Nothing is proposed as Supported. No maintainer statement establishes
  support, there is no numerical-validation report, and the package is
  version 0.1.0. Every implemented entry is Experimental, and the report
  states that the classification is the agent's proposal.
- Removed applies only where history shows a capability that once existed in
  this repository's code and was deleted.
- Rejected is not used: no recorded consideration-and-refusal was found.
- Uncertain classifications are marked "(review)" in the Status cell and
  explained in the report.

### Evidence columns
- Code/docs: module paths and the relevant README section.
- Verification: the specific test modules, labelled by evidence type, for
  example "unit: tests/test_operator.py" or "integration (tiny run):
  tests/test_integration.py".
  - Tests that check software behaviour are kept apart from numerical
    validity. A short note states that no entry has a numerical-validation
    report.
  - Where nothing exists, the cell says "none found".
  - The Stride outputs are listed as reference data, not as a recorded
    comparison.
- Decisions: "none recorded" where there are none.
- Source:
  - entries for capabilities predating this register use `#9`, the issue
    that created the entry, as the rules permit;
  - Removed entries also cite the removal commit and this repository's PR #2;
  - upstream PRs are cited only in full form
    (`ese-ada-lovelace-2025/<repo>#n`), and only if the repo name can be
    confirmed from merge messages. Otherwise the commit SHA is used. See open
    question 1.

### Decision records
A retrospective record is created only if a commit, PR, issue or document
states both the choice and its reason. Current evidence:
- The optimiser and leapfrog removal (`7c130ad` / PR #2) has no stated
  rationale.
- The inverse-crime baseline is described in the README, but no reason is
  given for switching the default.

So no records are expected. If none are written, the report lists the
candidate decisions with "rationale not recorded".

## Acceptance criteria
- `docs/features.md` has an entry for each capability in the list above,
  unless the report explains a merge or omission. IDs run sequentially from
  F-001.
- Every entry has non-empty Code/docs, Verification, Decisions and Source
  cells. "none found" and "none recorded" are explicit values.
- Every repository path cited in the register exists at the head commit, or,
  for Removed entries, is cited with the commit that removed it.
- Verification cells label the evidence type, and the register states that
  no entry has numerical-validation evidence beyond the tests listed.
- No entry is Supported or Rejected without a cited maintainer statement.
- No decision record states a rationale that is absent from the cited
  sources.
- `git diff --name-only main` lists only `docs/plans/9.md`,
  `docs/features.md`, `docs/reports/9.md` and any new `docs/decisions/D-*`
  files.
- The report lists what was inspected and the coverage limitations.

## Verification
- Path check: a scratch script (outside the repo, run with `python -I`) that
  extracts backticked paths from `docs/features.md` and checks them with
  `git ls-files` or `git cat-file -e <sha>:<path>`. The report lists the
  results.
- ID check: sequential, unique F-IDs.
- `git diff --name-only main` matches the scope.
- Optional, cheap: `python -m pytest tests/ -q`, to record whether the cited
  tests currently pass. If the environment lacks torch or jax, it is recorded
  as not run. A pass is software evidence only.
- Not run: inversions, notebooks, the Stride reference, or any numerical
  validation.
