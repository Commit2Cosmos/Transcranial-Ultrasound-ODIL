## Changes
### `.github/scripts/claude-task.js`
- `report` now calls `checkPlanDeliverable` for new planning runs (profile
  `plan`, no PR, successful Claude job). This replaces the check that only
  caught "branch pushed but no PR".
- The check passes in two cases:
  - **(a) Published plan:** `agent/issue-N` exists, `docs/plans/N.md` is a
    file at its head, and an open draft PR exists from it (`planPublication`).
  - **(b) Clarification:** a comment matches `isClarification`. It must be
    from `claude[bot]` with type `Bot`, created at or after `invoked_at`,
    carry the marker for this run ID and attempt, and contain a question line
    of at least 15 characters.
- Otherwise the check posts a fixed `PLAN_NO_DELIVERABLE` notice (run link
  with attempt, branch, plan, PR, clarification state, recovery instruction)
  and calls `setFailed('PLAN_NO_DELIVERABLE: …')`.
- `invocationProblem` checks the invocation metadata before any comment is
  searched. It requires all of the following:
  - a run ID;
  - a valid claude-job `run_attempt` equal to the report job's attempt;
  - a valid `invoked_at` that is not in the future.

  If any check fails, the notice reports "unverifiable: <reason>".
  Publication (a) does not depend on this metadata.
- `planInstructions` (new planning runs) tells the agent to end a
  clarification comment with `clarificationMarker(runId, attempt)`. An
  invalid identity throws, so the claude job fails before Claude starts.
- `setOutputs` accepts `runId`/`runAttempt` and adds the outputs
  `run_attempt` and `invoked_at`.
- Exports added: `clarificationMarker`, `invocationProblem`,
  `isClarification`.

## Interpretation and limitations
Established:
- With mocked API responses, the controller accepts only the two specified
  outcomes.
- It rejects lookalike, mistimed or uncorrelated comments.
- It reports unverifiable metadata explicitly instead of accepting or
  silently passing.
- The workflow arguments give the SDK `model: "opus"` exactly once.

Not established:
- **Live GitHub behaviour is untested:**
  - real `issues.listComments` `since` filtering (only a prefilter;
    `created_at` is re-checked);
  - `toJSON(needs.claude.outputs)` content;
  - that "re-run failed jobs" reuses the earlier attempt's outputs (smoke
    test 14).
- Which model the `opus` alias resolves to (smoke test 15).
- Whether the agent reliably includes the marker. If it does not, its
  clarification is rejected and the run fails with a notice: a conservative
  false negative. Recovery is a fresh `@claude plan`.
- **Remaining gaps, unchanged and documented:**
  - plan revisions, read-only requests and implementation runs pass on the
    Claude job result alone;
  - partial outcomes beyond (a) are not inspected;
  - question quality is not judged.
- If several open PRs share the task branch as head (for example with
  different bases), only the first is examined.
